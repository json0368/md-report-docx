# Markdown 语法支持情况

## 支持

| Markdown | 转换结果 |
| --- | --- |
| `# 标题` | 封面：Title 20pt 加粗居中；**下一个非空行**作副标题；再生成居中「目录」+ 目录域 |
| `##` `###` `####` | Heading 1/2/3（16/14/12pt 黑体加粗） |
| 普通段落 | Normal 12pt 宋体，首行缩进 2 字符，两端对齐；连续多行用空格合并成一段 |
| `**加粗**` | 黑体加粗 |
| `*斜体*` `_斜体_` | 斜体 |
| `***粗斜体***` | 加粗 + 斜体 |
| `~~删除线~~` | 删除线 |
| `` `行内代码` `` | 等宽字体（`fonts.mono`），字号用 `sizes.code` |
| `[文字](url)` | 真 Word 超链接，不是纯文本 |
| `- ` `* ` `+ ` | 无序列表，支持三层嵌套（2 空格一层），符号为 • ◦ ▪ |
| `1. ` | 有序列表，悬挂缩进，保留原编号不重新编号 |
| `> ` | 引用块，左侧竖线 + 缩进 |
| `---` `***` `___` | 分隔线 |
| `\| 表格 \|` | 边框 D9D9D9，表头灰底且跨页重复，行不拆断，列宽按内容自动分配 |
| `![alt](路径)` | 居中图片，宽度受 `images` 限制 |
| `图 n-n 题注` | Caption 10.5pt 居中，**写在图片下面**才生效 |
| `表 n-n 题注` | Caption 10.5pt 居中，**写在表格上面**才生效，并跟着下面的表格走 |
| ` ```语言 ` | 代码块，装箱上色；围栏可带缩进（例如写在列表项里），内容按开启围栏的缩进量整体去缩进 |
| `[n] 文献` | 悬挂缩进 0.65cm |

## 不支持

下面这些**不会报错**，会被当成普通文字排进正文：

- 脚注 `[^1]`、数学公式 `$...$`、定义列表
- Setext 标题（文字下面加 `===` 或 `---`）
- 自动链接 `<https://...>`、引用式链接 `[文字][ref]`
- 任务列表 `- [ ]`
- 缩进代码块（4 个空格、**不带围栏**的写法；带围栏的缩进代码块是支持的）
- 原始 HTML
- 表格单元格内的换行、合并单元格
- 嵌套表格

## 容易踩的坑

**图片带 title 会找不到文件。** `![alt](a.png "标题")` 会把 `a.png "标题"` 整个
当路径。要去掉 title 部分。

**表格竖线要转义。** 单元格内容里出现 `|` 时写成 `\|`。

**`#` 只能出现一次。** 每出现一个 `#` 就会生成一份封面 + 目录 + 目录域。
如果标题里没有 `cover.break_before` 指定的词（默认「课程设计报告」），
标题就不会换行——换个报告名时需要改这个配置。

**题注必须贴着图或表。** 图题注写在图片下面，中间不能有空行以外的内容；表题注写在
表格上面，中间同样只能有空行。正文里出现的「图 3-1」「表 3-1」不会被误判成题注，
正是靠这条规则。分不清方向的写法（比如「图 3-1」后面跟的是表格）不会被当成题注。

**表格列数要一致。** 列数不一致时会按最多列补齐并打印警告，不会中断转换。

**行内代码里的下划线是安全的。** `idx_orders_user_time` 不会被当成斜体，
因为斜体识别要求下划线两侧不是单词字符。

## 代码围栏的语言标记

围栏上的语言标记直接交给 pygments（自带 **600 个词法器**）选词法器，分词后映射到
9 类配色。实测能真正着色的常用标记：

| 类别 | 标记 |
| --- | --- |
| 数据库 | `sql` `mysql` |
| 后端 | `java` `python` `c` `cpp` `csharp` `go` `rust` `php` `ruby` `kotlin` `scala` `swift` `dart` `objectivec` |
| 前端与标记 | `javascript` `js` `typescript` `jsx` `tsx` `vue` `html` `xml` `css` `scss` `less` |
| 配置与脚本 | `bash` `sh` `shell` `powershell` `batch` `json` `yaml` `toml` `ini` `properties` |
| 构建与运维 | `docker` `makefile` `cmake` `nginx` `apache` `http` |
| 文档与数据 | `latex` `tex` `protobuf` `graphql` |
| 差异与终端 | `diff` `console` `markdown` |
| 其他 | `lua` `perl` `r` `matlab` `julia` `fortran` `pascal` `vbnet` `haskell` `erlang` `clojure` `groovy` `asm` `nasm` `verilog` `vhdl` `solidity` `abap` |

`sh` 和 `shell` 都指向 bash；bash 词法里 `mvn` `npm` `node` `mysql` `cd` `java` `git`
`docker` 不算关键字，脚本会把它们单独染成关键字色。

`diff` 和 `console` 不走 pygments，按行首符号上色：

- `diff` —— `-` 行红、`+` 行绿、`@@` 行蓝、`---`/`+++` 深色加粗。**不需要**写
  `--- a/x` 这类头部；pygments 的 diff 词法器反而会按文件名后缀挑子词法器，
  内容对不上时把整行变成 `Token.Error`，增删行就没了颜色。
- `console` —— `$` `>` `#` 开头的行，提示符染关键字色。pygments 的 console
  词法器会吞掉提示符之后的内容，不能用。

**只装箱不着色**：`text` `plaintext` `rst`。`text` 块里对齐的 ASCII 内容不会被
分页断开，适合放需要保持列对齐的终端输出。

**没有对应词法器**：`csv` `log` `regex` 等。这类标记会退回纯文本。

认不出的标记一律退回纯文本并照常装箱，不会报错，也不会丢内容。

另外，任何词法器只要分词后的拼接结果与原文不符，都会自动退回纯文本并在转换时
打印提示——宁可不着色，也不能丢字。
